## Current consumer boundaries

The supported native catalogue has23 source profiles. An installation may contain a subset: this instance has22, with Session Dashboard intentionally absent. Source qualification is required before evaluation; a lifecycle declaration is not execution authority. No missing add-on is reinstalled to satisfy a census.

Current Code Review receives the borrowed-root/admitted-write port in `default-application-runtime.ts`; its legacy standalone constructor is not evidence that native requests still sleep for five seconds. Observability's existing queries already had ID-indexed LIMIT2000 bounds before this repair; the remaining defect was synchronous collector/spool work on the turn thread. Root startup calling its migration owner is intentional; maintenance and worker opens must not acquire that owner.

Voice Pipeline's separate legacy direct-message writer is not installed or accepted by the current native source catalogue. It is not certified for native activation here. Ad hoc root scripts such as historical token backfill, session-archive import and benchmark writers run only by explicit offline/operator invocation. They are not scheduler/runtime child entrypoints; this work neither runs them against live files nor grants them new authority. Their documented target/format/ownership restrictions remain.

## Retired legacy SQL execution

`introspect_sql` had only a legacy built-in factory/metadata/documentation path; the current native tool registry and public host API do not register it. The legacy executor used a shared writable connection, lexical filtering and unbounded materialisation. Adding a new native SQL surface to justify it would contradict #1828's retirement requirement.

The candidate removes that executor, factory/hook, built-in capability/toolset and service-preparation records. Its legacy-only tests are replaced by registration/source-absence negatives, while `messages` remains available. Native execution gains no arbitrary SQL authority. Opaque saved `additionalDefaultTools` values are preserved and unknown names are ignored; an explicitly supplied third-party tool is not silently assigned the retired built-in's read-only safety proof. Normal PR review must approve this legacy retirement before merge.

## Outcome and retry matrix

| Boundary | Permitted recovery | Forbidden shortcut |
|---|---|---|
| BEGIN acquisition before callback | Yield and retry within the existing deadline, repeating source/owner/abort checks | Sleep inside SQLite on the turn thread; retry an entered callback |
| Successful task, delayed S07 completion | Retain exact result/request and repair the same durable decision; keep admitted store alive | Re-run shell/model/tool, declare execution failed merely because persistence waits |
| Committed decision, lost observer acknowledgement | Re-observe/replay the existing idempotent decision using its original identity | Turn an unknown commit into not-applied or change its hash/time/result |
| Unentered peer notification API | Keep notification-pending, explicitly retry after repair | Assume every thrown API error proves non-entry |
| Entered peer enqueue or failed receipt storage | Retain delivering/unknown across reopen; inspect before action | Automatically enqueue/send again because local acknowledgement is missing |
| Moved/replaced file or uncertain worker close | Refuse new ownership; join existing cleanup or fail closed | Keep checkpointing an unlinked file, steal a lifetime or fabricate a successful drain |
| Permanent storage failure or uncooperative external effect | Preserve known evidence and explicit uncertainty; operator recovery is a separate decision | Claim universal immunity, exactly-once arbitrary effects or authorised replay |

No new financial admission, hold, debt or spending owner is introduced. Historical financial data and passive cost/token/cache/reasoning telemetry remain data.

## Focused acceptance and remaining publication gate

New counterexamples reproduce the original moved-handle registration, two-attempt completion result loss and root-migrating dry-run defects. Unchanged limits/assertions are retained. Current focused evidence includes actual12-second WAL completion outage after poll stop with one shell execution,100 due occurrence renewal recovery during a real six-second writer outage, actual60-second lease expiry while a tool's writer remains held, cancellation/close, no-op idle polls, callback-once, SQLite reopen, worker lifecycle and restore-format controls.

The Restic fixture stages only disposable data: actual SDK submissions/entries retain their bytes, atomic parent/child probe pairs retain FK consistency, the manifest excludes live sidecars, and reopening the supported SQLite format does not invoke the provider again. Existing backup settings are disabled and this task never enables or runs a live backup.

Add-on candidates require public publication and exact Core source-profile/default/pin updates before current native factory qualification can accept them. Installed0.1.24/0.3.8 files and immutable2f8b60e/08746aa fixtures are untouched. The optional old Remote Peer cross-worktree fixture imports a retired host queue and cannot certify SDK1.5.2; its failed current-root attempt is retained. Current native peer/default-factory acceptance must use the supported SDK boundary after coordinated publication, not restore that legacy queue.

Complete final-source host/native/package qualification and measured aggregate workloads remain separate from this census. Failed, skipped-only and partial receipts are not combined into a full pass. No issue or epic is closed by this document alone, and no deployment, live backup/restore, retention change, credential mutation, peer send or restart is authorised by it.
