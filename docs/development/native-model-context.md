# Native candidate context admission

Model selection estimates one prospective transcript in SDK token units. Instructions are resolved sections; selected tool declarations are positional system contributions. Neither is charged again after the SDK transcript or applicable provider usage already represents it.

`host-model-context.ts` retains a small, read-only projection because pinned pi-durable 1.4.0 exposes committed `ContextView` and resolved `Agent`, but no non-persisting candidate preparation API. The upstream request is earendil-works/pi#11652; its automatic contributor-gate closure does not supply an API. The projection uses public SDK types and transcript helpers. It creates no durable entries, edits, tasks, configuration, recovery loop or provider request.

## Snapshot and ordering

Preparation renders the candidate's resolved sections once, outside the configuration transaction. It preserves ordered replay, tags, removals, re-additions, schema replacement, declaration order and `constrainedSampling`. Unchanged sections and schemas add nothing. Native generation remains responsible for the actual request.

A pending reset/compaction head requires a complete baseline. The projection removes only contributions attributed to retained native `SystemEntry` records, then adds that baseline. It requires aligned entry/contribution arrays and unique object-reference membership in both contributions and model messages. Ambiguous provenance or non-system replacement content refuses admission. Custom host system messages survive. This check establishes provenance for the captured view without assuming reference identity across SDK versions.

Initial baseline placement includes existing dialogue and edited or omitted old system entries. Differential tests compare projections with requests recorded by actual native generation, including pending compaction and custom host systems. Synthetic probes supplement those journeys.

## Authority and limits

The existing source, owner, abort, registry/default-extension, configuration and append-frontier fences remain active through selection commit. Context order after compaction is not the append frontier. Owned model tools require prepared admission; their messages-only fallback is removed.

The SDK estimator supplies text/token interpretation. Cache-exclusive and cache-inclusive provider totals retain conservative coherence checks; metadata and opaque signatures do not become text tokens. Framing allowances, image refusal and genuine input overflow remain admission checks. The invented full nominal output plus8192 reserve veto is removed. A refusal leaves history and the persisted choice unchanged. Selection does not compact or replay accepted input.

Scheduled allocation checks the inherited parent snapshot. Sections render with the parent conversation ID and environment. This does not establish an exact child-ID-dependent request preview. Likewise, arbitrary later renderer/document changes and write-capable `beforeRequest` hooks are outside the captured snapshot. Plan, Goal and Observability request hooks require separate qualification under epic #1857.

Remove the projection when a public SDK facility provides equivalent rendered contributions, selected declarations, baseline/provenance semantics and applicable-usage accounting. Public `GenerationTask.prepare` commits system/task state and can invoke compaction, so it cannot supply this read-only observation. No private package imports, fake planner runtime or SDK/storage version changes are needed. Expense enforcement retirement belongs to #1875; token/pricing/provider-cost observation and exact terminal recovery remain required.

## Stock SDK output boundary

The Root `model-request-preview.ts` boundary calls the fixed public OpenAI Completions, Responses or Azure Responses adapter with its own `onPayload` interceptor. It observes the final cap after sampling/minimum/omission rules, then stops before send. The public clamp supplies the allowance; its private constant is not copied. Synthetic noncredentials, empty headers/environment and fail-closed fetch/preconnect prevent provider traffic. Caller hooks are refused, not executed. Only detached bounded metadata returns across the Root/private boundary.

Public runtime/catalogue inspection identifies eligible builtins. Native/custom/extension producers, auth-dependent modes and unsupported APIs remain unknown. Their model selection checks input only, without claiming full request fit. Physical/provider identity and abort checks fence awaited metadata. The existing admission owner captures this observation before SQL; no provider decorator, preview registry, second ledger or cached request state is introduced.

Remove this87-line boundary when an approved public SDK operation supplies equivalent auth-independent final request bounds. It replaces the host's invented output veto; the separate instruction/tool projection remains necessary.

Regrets0.3 uses the SDK text estimator on the final compact packet and removes its bytes/2 decision veto. The durable host owns configuration, history, approval, prompt and execution. The SDK entry registers declarations/resources and rejects unbound execution. Ambient KV/memory fallback, access parsing, registry-based completion and duplicate SDK handlers are deleted. Core also deletes two unused host forwarding helpers and the old prompt lifecycle adapter. The source gate admits only the exact repaired0.3 backend; the native fixture is an immutable public commit. Dashboard0.2.6's previously accepted manifest is pinned alongside it.

## Browser projection

Classic and Visual context meters display the backend percentage. They add no token margin or local percentage fallback. Unknown counts and percentages remain unavailable; a reported zero stays zero. Classic session metrics also omit an unknown percentage. Existing explicit compaction controls remain separate from rendering and model selection.

Visual's model catalogue contains only backend results. The preset Copilot model/window table is removed, and an empty catalogue clears old rows using the existing empty-result surface.

Thinking menus use the current backend model snapshot, including cold load and capability revocation. Picker GETs and switch confirmations publish complete backend metadata through the existing shared model-state event rather than partial current-model/thinking callbacks. Empty confirmations clear stale rows even when a switch is not confirmed; replies for a different active chat do not update the picker. Visual no longer keeps preset levels or a per-picker thinking snapshot; Classic no longer reads thinking choices from its stale popup catalogue. The unused Visual context-window fallback signal is removed.

## Thinking capabilities

The root/private bridge copies `thinkingLevelMap` as detached, frozen JSON, limited to the SDK's public thinking-level keys. Null-disabled and extended levels retain their native meaning. Physical reasoning/map changes refuse new transport rather than silently changing the selected effort.

Native API discovery, cycling and commands use the public SDK's canonical capability keys. An explicitly disabled `max` is not a request for legacy `xhigh`; an empty SDK capability list does not invent `off`. Historical label adapters remain on the separate legacy-session/extension path. Original off tests are retained alongside owned-tool rejection, next-request max/xhigh and SQLite reopen checks.

Transport receives a detached physical-model snapshot. Source, lifetime, policy and current physical compatibility are checked again after awaited dispatch admission. The public SDK still awaits the final header hook before provider entry; revocation queued after its final synchronous check remains a documented limitation. Tests retain that counterexample alongside the earlier-gap zero-dispatch regression. Paid-terminal retention and stored-outcome recovery are unchanged.

## Hook overflow and recovery

Plan and Goal materialise source/task-owned hidden snapshots through public commits before dispatch. They repair only their owned trailing suffix at the SDK's pinned cutoff. Goal's request-only rules and Observability's system contribution remain request hooks. Moving those snapshots into mutable sections would change historical ordering and recovery authority.

Actual offline Codex-adapter regressions send oversized hook contributions, observe a real HTTP400 context rejection and require one provider call, an exact unanswered/model-error terminal and unchanged history/terminal after SQLite reopen. Retry and automatic compaction are disabled in those controls. A separate rejection control proves that the test bridge settles its private stream and retains the original producer failure. Existing explicit native compaction, changed/cleared Plan, Goal identity and source-revocation cases remain.

Observability's source-bound request hook is separately exercised through real controller/Delegate late-ack recovery. Actual default-factory Plan, Goal and infrastructure cases verify the installed native exports and reopen. These are bounded compositional checks; selection still cannot predict arbitrary future write-capable hook changes.
